# Контракт Domain ↔ ESB

Уточнённая реализация контракта от 25 октября 2026 года. Внешний источник спецификации задаёт бизнес-поля; ниже зафиксированы маршруты ESB и двусторонний WebSocket-диалог Константина.

## Общие правила

- `companyId` и `sourceId` — UUID. `sourceId` — ID конкретной записи `news_links.id`.
- Защищённые HTTP-запросы и WebSocket handshake содержат `Authorization: Bearer <ESB_API_KEY>`.
- Тип агента задаётся query-параметром `/call?agent=<type>`. Вызовы Hermes асинхронны.
- ESB — единственный компонент с credentials и подключениями к PostgreSQL, ClickHouse и S3. Hermes использует хранилища только через MCP ESB.
- PostgreSQL хранит очередь, чаты, профильные ревизии, реестр входящих источников и сохранённые события Константина. ClickHouse хранит новости, универсальные факты, связи факт–компания, наблюдения и агрегаты. S3 хранит Markdown-профили.
- Время передаётся в ISO 8601 с часовым поясом. Неизвестные значения полей профиля передаются как `null`.

## Профиль компании — Валере

`POST /call?agent=valera` принимает JSON от Domain. ESB также принимает оболочку `{ "agent": "Валера", "payload": {...} }`, но query-параметр остаётся авторитетным выбором типа агента.

```json
{
  "companyId": "11111111-1111-4111-8111-111111111111",
  "profileRevision": 1,
  "company": {
    "syntheticU": "U_80",
    "orgType": "КОММ_ОРГ",
    "ownershipForm": "ЧАСТНАЯ СОБСТВЕННОСТЬ",
    "mainOkvedCode": "25.61",
    "mainOkvedName": "Обработка металлов и нанесение покрытий на металлы",
    "negativeMark": false,
    "workersSparkGradation": null,
    "hasLeasing": true,
    "revenueCompany": 1423218135,
    "city": "г. Екатеринбург",
    "region": "Свердловская область"
  }
}
```

Ответ `202 Accepted`:

```json
{
  "status": "accepted",
  "companyId": "11111111-1111-4111-8111-111111111111",
  "profileRevision": 1,
  "callId": "..."
}
```

Пара `(companyId, profileRevision)` — ключ идемпотентности. Валера через MCP формирует Markdown и обновляет PostgreSQL-настройки метрик вместе с номером ревизии. ESB сначала фиксирует ревизию и метрики в PostgreSQL, затем перезаписывает стабильный S3-ключ `companies/{companyId}/profile.md`. Повтор той же ревизии завершает запись после частичного сбоя; более старая ревизия отвергается.

При приёме вызова Валеры ESB сразу резервирует ревизию в PostgreSQL и помечает профиль как ожидающий S3-синхронизации. Поэтому старый анализ сразу становится неактуальным. Пока S3-запись не подтверждена, `GET /call?agent=konstantin` вернёт `409 profile_update_pending`; повторите запрос после завершения вызова Валеры.

## Новость или аналитика Альфа-Банка — Серёже

`POST /news` принимает очищенный текст материала (максимум 1 MiB UTF-8):

```json
{
  "sourceId": "22222222-2222-4222-8222-222222222222",
  "text": "Очищенный текст новости или аналитического материала."
}
```

ESB вызывает Domain `GET {DOMAIN_API_BASE_URL}/internal/news-links/{sourceId}` с `Authorization: Bearer $DOMAIN_API_TOKEN`. Domain возвращает:

```json
{
  "sourceId": "22222222-2222-4222-8222-222222222222",
  "companyId": "11111111-1111-4111-8111-111111111111",
  "canonicalUrl": "https://alfabank.ru/example/analysis.pdf",
  "materialKind": "alpha_analysis",
  "mediaType": "application/pdf",
  "title": "Анализ рынка",
  "publishedAt": "2026-10-25T09:00:00Z"
}
```

`materialKind`: `external_news` или `alpha_analysis`; `mediaType`: `application/pdf` или `text/html`. Ответ `POST /news` — `202 Accepted` с `status`, `sourceId` и `callId`. Повтор `sourceId` не создаёт новую запись источника или второй вызов при идентичном запросе. Неизвестный ID даёт `404`.

ESB регистрирует источник и компанию в PostgreSQL до запуска Серёжи. Серёжа сохраняет текст и универсальные факты в ClickHouse с типом материала, ссылкой и `sourceId`. Настройки Domain API задаются в `DOMAIN_API_BASE_URL` и `DOMAIN_API_TOKEN`.

## Получить анализ / подписаться на поток Константина

`GET /call?agent=konstantin` с JSON-телом:

```json
{"companyId":"11111111-1111-4111-8111-111111111111"}
```

Если актуальный анализ уже есть, ESB отвечает `200` с полным текстом, доказательствами, `analysisId`, `messageId` и `conversationId`. Если анализа нет или он устарел, ESB ставит Константину асинхронную задачу и отвечает `202`. Для запуска нужен сохранённый профиль компании; без него ESB возвращает `409 company_profile_not_found`:

```json
{
  "status": "processing",
  "companyId": "11111111-1111-4111-8111-111111111111",
  "conversationId": "33333333-3333-4333-8333-333333333333",
  "requestId": "66666666-6666-4666-8666-666666666666",
  "streamUrl": "/stream?companyId=...&conversationId=...&requestId=...",
  "history": [],
  "historyHasMore": false,
  "historyFrom": "2026-09-25T00:00:00Z",
  "historyTo": "2026-10-25T00:00:00Z"
}
```

Оба ответа (`200` и `202`) также содержат страницу истории переписки из PostgreSQL: сообщения пользователя и ответы Константина для этой компании. По умолчанию возвращаются последние 30 дней и не более 100 сообщений. Можно задать `historyFrom` и `historyTo` в RFC 3339; один период не может превышать 90 дней. При `historyHasMore: true` запросите следующую страницу, передав те же границы периода и `beforeMessageId`, равный `historyNextBeforeMessageId` из ответа. Так клиент загружает старые сообщения порциями, не сканируя всю переписку за один запрос.

Клиент подписывается WebSocket-соединением на маршрут `/stream`, используя `streamUrl`. Маршрут зарезервирован только за Константином и не принимает `agent` в query. Уведомление появляется после сохранения полного текста и доказательств в PostgreSQL.

`POST /call?agent=konstantin` с тем же телом `{ "companyId": "..." }` асинхронно ставит анализ в очередь и возвращает `202 Accepted` с `call_id`. Операция идемпотентна для пары компании, ревизии профиля и ревизии входящих материалов. Затем `GET /call?agent=konstantin` возвращает актуальный результат либо данные для подписки на `/stream`.

Константин читает профиль S3, настройки метрик PostgreSQL и предварительно агрегированные факты, наблюдения и итоги ClickHouse через инструменты единого MCP ESB. Обязательного периода нет. `originKind` в доказательстве: `fact`, `bank_view` или `ai_inference`; каждое доказательство содержит неизменённый `sourceId`.

## Двусторонний диалог через WebSocket `/stream`

После handshake клиент может отправлять кадры вопроса:

```json
{
  "kind": "question",
  "requestId": "77777777-7777-4777-8777-777777777777",
  "companyId": "11111111-1111-4111-8111-111111111111",
  "conversationId": "33333333-3333-4333-8333-333333333333",
  "analysisId": "44444444-4444-4444-8444-444444444444",
  "text": "Почему эта новость важна для нашей компании?"
}
```

Сначала ESB отправляет `accepted` с `requestId`; после выполнения — один полный кадр:

```json
{
  "schemaVersion": 1,
  "kind": "assistant_answer",
  "requestId": "77777777-7777-4777-8777-777777777777",
  "companyId": "11111111-1111-4111-8111-111111111111",
  "conversationId": "33333333-3333-4333-8333-333333333333",
  "analysisId": "44444444-4444-4444-8444-444444444444",
  "messageId": "88888888-8888-4888-8888-888888888888",
  "text": "Эта новость важна из-за возможного изменения стоимости сырья для вашего направления.",
  "evidence": [
    {"sourceId":"22222222-2222-4222-8222-222222222222","originKind":"fact"}
  ],
  "createdAt": "2026-10-25T09:07:00Z"
}
```

Для исходного анализа `kind` равен `analysis_result`. `messageId` уникален. Прогресс и частичные токены не отправляются. При переподключении клиент передаёт `afterMessageId` в URL `/stream`; ESB повторно отдаёт сохранённые более новые сообщения. Domain может дедуплицировать их по `messageId`.

Если заданный `analysisId` не существует или стал неактуален, ESB отвечает `analysis_not_ready`. Тот же `requestId` идемпотентен. Новый `sourceId` компании или более новая `profileRevision` делает старый анализ неактуальным.

Вопросы Константину передаются только кадрами WebSocket `/stream`; отдельного HTTP-маршрута для вопросов нет.

## Ошибки

Ошибки HTTP возвращаются как JSON `{ "error": "stable_code" }`. Основные коды: `unauthorized`, `invalid_news_request`, `news_source_not_found`, `analysis_not_ready`, `idempotency_key_conflict`. Все ответы и сообщения чата принадлежат ESB; прямое подключение Domain к PostgreSQL запрещено границами сервиса.
