# Спецификация E2E

Публичный контракт Domain ↔ ESB описан в [руководстве интеграции](../docs/integration.md) и сгенерированных [API-спецификациях](../docs/api/README.md). Этот документ фиксирует, что именно проверяет E2E-прогон.

## Границы прогона

Тест запускает собранный ESB и обращается к его HTTP, WebSocket и MCP интерфейсам. PostgreSQL, ClickHouse и MinIO — реальные одноразовые контейнеры. Hermes — детерминированный mock; вызов LLM не выполняется. Проверяются маршрутизация, авторизация, очередь и статусы, репозитории, схемы MCP, запись профиля в S3 и повтор WS-сообщений.

E2E использует отдельное Compose-имя и отдельные volumes. Обычный Compose-проект и его volumes не затрагиваются. Atlas применяет PostgreSQL baseline; ClickHouse baseline запускается через `clickhouse-client`, чтобы E2E не требовал Atlas Pro токена.

## Матрица сценариев

| Интерфейс | Сценарии |
| --- | --- |
| Health и авторизация | Открытый `/healthz`, защищённый `/readyz`, отказ без bearer-токена |
| `POST /call?agent=...` | Вызовы Валеры и Константина, вызовы Савелия и Кеши, очередь Серёжи, повторы, некорректный агент, неверные данные и конфликт ревизии профиля |
| `GET /call?agent=...` | Чтение вызова и отчёта Кеши; анализ и батч-история Константина с периодом и курсором; неверный агент или отсутствующее тело |
| `GET /call?data=facts` | Связанные с компанией и универсальные факты; фильтры по источнику, новости, компании, категории, сущности, материалу и периоду; exclusive `periodTo`, 90-дневное ограничение, лимит, пагинация и ошибочные фильтры |
| WebSocket `/stream` | Авторизация без `agent` query, доставка анализа и ответов, вопрос/подтверждение, replay после reconnect, устаревший анализ и некорректный курсор |
| MCP `/mcp` | Initialize, discovery и вызов каждого зарегистрированного инструмента через настоящий MCP-клиент |
| Аналитика метрик | девять каталожных типов, UUID строки PostgreSQL, среднее без весов, отдельное среднее вероятностей, фильтрация по времени новости, null/zero, повторные наблюдения, уникальные упорядоченные ссылки, пустые и перевёрнутые периоды |
| Очистка | отдельные циклы статуса и retention, потерянная отправка без `hermes_run_id`, подтверждённый повтор только в пределах retry-бюджета, защита активного вызова с неизвестным статусом, возрастные политики по категориям, ограниченная пачка, безопасный повтор после частичного сбоя |
| Хранилища | PostgreSQL хранит чаты и настройки метрик; ClickHouse — новости, факты, связи и наблюдения; MinIO проверяет сохранение профиля; новая ревизия профиля или источник инвалидируют старый анализ |

## Запуск

Из корня репозитория:

```sh
./predictor/tests/run-e2e.sh
```

Скрипт поднимает изолированные зависимости, применяет миграции, запускает ESB и Go-клиент E2E. При завершении удаляются только контейнеры и volumes тестового Compose-проекта.

## Проверяемые правила

- Запуск агента возвращает `202 Accepted` и идентификатор вызова; статус и результат читаются отдельным запросом.
- Профиль считается готовым после подтверждённой записи Markdown и настроек метрик.
- Повтор с тем же источником или ревизией профиля идемпотентен; конфликтующее содержимое отклоняется.
- Успешная обработка новости подтверждается marker, хешем, метаданными и числом фактов; сырой текст остаётся до истечения retention после `processed_at`.
- У необработанной новости текст в ClickHouse удаляется только при конечном failed/cancelled/interrupted вызове Серёжи; retry payload PostgreSQL остаётся доступным, пока обработка не подтверждена.
- Удаление сырого текста не удаляет метаданные, факты, связи, наблюдения, итоги или анализ. Метаданные защищены ссылками фактов/наблюдений, а факты — ссылками компаний/наблюдений. ClickHouse mutation ждёт применения и проверяется через `FINAL`.
- Каждый cleanup проход ограничен размером пачки и сериализован PostgreSQL advisory lock. Вызов с активным статусом или неустановленным статусом Hermes не удаляется.
- Политики сообщений Константина и резюме разделены; при `never` сообщения и история Константина сохраняются, а вызов с внешними ссылками остаётся компактной tombstone-записью.
- Факты читаются ограниченными страницами; глобальная выдача не включает привязки к компаниям.
- Итоги метрик пересчитываются по запросу и не пишутся в ClickHouse. Выборка включает обе временные границы времени публикации новости; время вставки наблюдения не используется.
- Нулевое значение учитывается, `null` исключается; вероятность не взвешивает значение. Пустой результат имеет null итоги, нулевые счётчики и пустые ссылки.
- `calculate_all_metric_totals` сохраняет настроенные строки без предиктов и выдаёт их в порядке каталога; неизвестная компания без настроек возвращает пустой список.
- Ответ Константина и доказательства сохраняются до отправки по WebSocket. Сообщения содержат source ID и восстанавливаются при переподключении.
- История чата возвращается из PostgreSQL батчами с периодом и курсором, а не целиком.
- Контракт `202 Accepted` использует `call_id` для всех типов агентов, включая Валеру; для чтения статуса передаются тот же `agent` и `call_id`.

## Не входит в E2E

Mock Hermes не проверяет качество промптов и точность рассуждений модели. E2E подтверждает протокол и прохождение данных, но не качество ответов реального LLM.
